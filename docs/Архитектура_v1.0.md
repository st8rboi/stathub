# Архитектура платформы Статхаб для администрирования спортивных соревнований

## Введние

! Сначала футбол, потом по аналогии мастшабирование на другие виды спорта !

- **Масштаб**: платформа для множества независимых организаторов лиг
- **Продуктовая модель**: единая публичная витрина, объединяющая матчи/таблицы/статистику разных организаторов (Аналог Flashscore) — см. 2.1
- **Клиенты**: публичные (болельщики, игроки) и административные (организаторы лиг)
- **Мобилка**: React Native (см. раздел 11)
- **Бэкенд**: C# / ASP.NET Core, PostgreSQL
- **Киллер чфича**: судьи могут вести матч в условиях нестабильного интернета (белых списков), надо реализовать запись в локальное хранилище и синхронизацию, когда появляется инет.

## 1. Общая структура (модульный монолит)

**Модульный монолит** на ASP.NET Core, модули разделены как отдельные проекты с чёткими границами; при росте любой модуль выносится в сервис.

| Модуль                  | Ответственность                                            |
| ----------------------- | ---------------------------------------------------------- |
| **Identity**            | Аутентификация, роли, привязка пользователя к организатору |
| **Leagues/Tournaments** | Лиги, сезоны, этапы, расписание                            |
| **Teams/Players**       | Команды, заявки, игроки                                    |
| **Matches/Live**        | Протокол матча, приём событий, пересчёт состояния          |
| **Standings/Stats**     | Таблицы, статистика, правила                               |
| **Notifications**       | Push-уведомления                                           |
| **Media**               | Логотипы, фото (объектное хранилище, не Postgres)          |
